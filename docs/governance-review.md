# Track B Cloud Governance Control Assessment

| Control | Status | Finding | Remediation / Mitigation |
| :--- | :---: | :--- | :--- |
| **1. Least Privilege** | **Pass (with gaps)** | Each Worker binds strictly to its required R2 buckets and queues; consumer Workers (`processor`, `notifier`, `analytics` queue) expose no public HTTP ingress; R2 API token is restricted to `kijani-receipts-staging` only; Jenkins token is scoped to Workers, R2, Queues, and Account Read. **Gaps:** Cloudflare management scopes are account-wide rather than per-Worker, and one shared `API_KEY` per stage authorizes both ingestion (`POST /receipts`) and analytics reads (`GET /summary`). | Split `API_KEY` into separate ingest-only and read-only tokens per service, and restrict Cloudflare API tokens to specific Workers/resources where supported. |
| **2. Encryption in Transit & At Rest** | **Pass (with gaps)** | Public `*.workers.dev` endpoints enforce `TLSv1.3` (confirmed in `wrangler tail` edge telemetry). Server-side encryption at rest on R2 and Queues relies on Cloudflare platform defaults (cited per Cloudflare R2 Data Protection docs, unverified via customer-managed keys). **Gap:** Internal Minikube `ClusterIP` traffic (`kk-payments-service:3001`) uses plain HTTP inside the local cluster. | Enable mutual TLS (mTLS) via a Kubernetes service mesh (e.g., Linkerd or Istio) for in-cluster pod-to-pod traffic in production. |
| **3. No Hardcoded Secrets** | **Pass (with gaps)** | Automated `scripts/secret-scan.sh` enforces static checks in CI; `docs/credential-audit.md` confirms `0` matches for all 5 live credentials across git history and Jenkins logs (`#1`–`#3`); runtime secrets live in Jenkins Credentials and Kubernetes Secrets. **Gaps:** Placeholder test string `mock-secret-key-12345` and the `workers.dev` subdomain appear in git history; two staging/production API keys were displayed in a shared terminal during initial generation and have not yet been rotated. | Rotate both `kk-api-key-staging` and `kk-api-key-production` via `openssl rand -hex 24` and redeploy through Jenkins after capstone evaluation. |
| **4. Naming & Tagging** | **Pass (with gaps)** | Resources follow a consistent environment-suffixed convention (`kk-<service>-<stage>`, `kijani-<purpose>-<stage>`, and `{service}-{resource}.yaml` in `k8s/`). Bucket names deliberately omit the redundant service prefix (`kijani-receipts-staging` rather than `kijani-payments-receipts-staging`) to avoid breaking live queue notifications. **Gap:** Cloudflare free-tier R2 buckets and Workers lack an automated resource-tagging mechanism in Wrangler templates. | Enforce standard metadata labels across Kubernetes manifests (`app`, `environment`, `managed-by`) and adopt Cloudflare account-level resource tagging if upgraded to an Enterprise plan. |
| **5. Auditability** | **Pass (with gaps)** | All four Workers emit structured JSON logs (`service`, `stage`, `event`, `orderId`, `timestamp`); Jenkins archives immutable `approval.txt` records (`Approver`, `Reason`, `Timestamp`); malformed receipts are preserved under `quarantine-*` prefixes. **Gaps:** R2 bucket access logs are not enabled on the free tier, and dead-letter queues (`*-dlq-*`) do not trigger automated alerts. | Configure an R2 Logpush job (or audit Worker) for object-level access trails and attach a scheduled Worker or webhook consumer to alert on DLQ depth `> 0`. |
| **6. Data Residency** | **Fail (Free-Tier Constraint)** | R2 buckets are provisioned without an explicit location hint (`AWS_REGION: "auto"`). Live `wrangler tail` telemetry confirmed requests originating in Nairobi, Kenya were served through Cloudflare colo `OTP` (Bucharest) and `BUD` (Budapest). Per Cloudflare R2 documentation, Cloudflare does not currently offer an Africa-region R2 jurisdiction constraint (only `WEUR`, `EEUR`, `WNAM`, `ENAM`, `APAC`). | Document regional routing behavior in `README.md` and configure explicit R2 jurisdiction hints (e.g., `EEUR` or `WEUR`) when creating buckets for regulated workloads. |
